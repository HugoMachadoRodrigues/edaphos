# Provenance Inventory

**Package:** `edaphos` 0.9.0 — Digital Soil Mapping with Causal,
Physics-Informed and Generative Methods **Commit:** `8f23ddf`
**Compiled:** 2026-08-28

This document answers a specific question: **does `edaphos` distribute
soil data it has no right to distribute?** In particular, does it
contain the datasets `datsoilspc` or `svrc_example`, or material from
the USDA — the Kellogg Soil Survey Laboratory (KSSL), the National
Cooperative Soil Survey (NCSS), RaCA, SSURGO or STATSGO?

Every number below is measured from the repository rather than asserted,
and §7 gives the commands to re-derive each one. The machine-readable
form is
[`tools/provenance-inventory.json`](https://hugomachadorodrigues.github.io/edaphos/tools/provenance-inventory.json),
regenerated by
[`tools/provenance-inventory.R`](https://hugomachadorodrigues.github.io/edaphos/tools/provenance-inventory.R)
in about two seconds.

## 2. USDA, Kellogg / KSSL, NCSS, RaCA, SSURGO, STATSGO

Here the honest answer is more interesting than a flat denial, so it is
given in full.

### 2.1 What is genuinely present

**Two of the 1,095 soil profiles behind the Cerrado case study carry the
WoSIS dataset identifier `US-NCSS`.** They were obtained through ISRIC’s
WoSIS 2019 snapshot, not from any USDA service. WoSIS records their
licence, and it is this:

| Licence recorded by WoSIS                                  | Profiles |
|------------------------------------------------------------|----------|
| Attribution 4.0 International (CC BY 4.0)                  | 842      |
| Attribution-NonCommercial 4.0 International (CC BY-NC 4.0) | 250      |
| CC0 1.0 Universal Public Domain Dedication                 | 1        |
| **U.S. Public Domain** — `usa.gov/publicdomain/label/1.0`  | **2**    |

The two `US-NCSS` profiles are exactly the two profiles that WoSIS
labels **U.S. Public Domain**. That is the U.S. Government’s own
public-domain dedication, which places no restriction on redistribution.

**No record-level data from those two profiles is shipped.** What the
package contains is a five-row aggregate table — one row per
contributing dataset, holding a count, a year range and a median:

        dataset_id n_profiles year_min year_max soc_median_gkg
    1    BR-Cooper        838     1960     1986           13.8
    2   BR-Bernoux        250     1973     1982           11.8
    3   BR-RioDoce          4     1982     1982           25.2
    4      US-NCSS          2     1967     1980           27.0
    5 WD-Mangroves          1     2010     2010           33.2

This is the only occurrence of any of the six USDA-related terms inside
any shipped data artefact.

### 2.2 What is present but is not data

**`USDA` and `NRCS` appear in exactly two files**, `R/fixtures.R` and
the manual page generated from it, and in both cases the sentence is a
disclaimer telling users to obtain real data themselves:

> `edaphos` does not bundle or redistribute third-party soil data. Real
> profiles are the user’s to obtain from the upstream services directly
> — ISRIC WoSIS, the SoilData Dataverse, USDA-NRCS — under those
> services’ own licences, which vary per record.

**One hyperlink** in the published documentation site points to
`https://ncss-tech.github.io/aqp/reference/sp4.html` — the reference
page for the `sp4` example dataset of the `aqp` R package, hosted on the
NCSS technical team’s GitHub organisation. It is a link to another
package’s documentation. No data crosses it.

### 2.3 What looked present and is not

A naïve byte-level search of the repository reports `KSSL` once, `RaCA`
once and `NCSS` in a Word manuscript. **All three are coincidence, not
content.** `.rds` files are xz-compressed, `.docx` is a ZIP and `.png`
pixel data is DEFLATE — a four-letter sequence turns up in compressed
streams by chance. Decompressing each one first and searching the actual
content resolves all three:

| Apparent hit | Where the bytes are | What it actually is |
|----|----|----|
| `KSSL` | PNG image data of a DAG plot | the byte run `ksSL` inside an IDAT stream |
| `RaCA` | xz stream of `benchmark_wosis_p4_p5_p7.rds` | `RACA` between high-bit bytes; absent after decompression |
| `NCSS` | DEFLATE stream of `paper/plos-manuscript.docx` | absent from the unzipped XML |

`Kellogg`, `SSURGO` and `STATSGO` return zero occurrences on every
surface, compressed or not.

## 3. What the package actually ships

27 data artefacts: 24 `.rds` bundles in `inst/extdata/` and 3 `.rda`
datasets in `data/`.

**The three exported datasets are synthetic.** `br_cerrado`, `br_amazon`
and `br_pantanal` are each a 45 × 45 pixel grid of simulated covariates
with a synthesised SOC response, documented as such and generated by
`data-raw/prepare_br_cerrado.R`. The two `fixture_*` bundles are
likewise synthetic stand-ins.

**Thirteen of the 27 bundles carry a strip note.** On 2026-08-28, commit
`8f23ddf` (“fix!: stop shipping third-party soil measurements”) ran
`data-raw/strip_third_party_records.R`, which removed every element
carrying a third-party measurement or an upstream identifier while
keeping the aggregate tables the published results rest on. The manifest
of what was removed is committed at
`data-raw/build/stripped_elements.csv`, which names each removed element
and the reason, for example:

- `piml_coverage` — `$coverage` (150 rows): `$truth` was verbatim
  upstream laboratory SOC keyed to a real profile identifier
- `pilar8_real_pedons` — `$cv` (5,458 rows): measured SOC at 7 depth
  nodes for 1,022 real pedons
- `capstone_campaign_results` — `$wosis_profiles` (250),
  `$piml_profile_obs` (9): real coordinates and measured SOC
- `piml_prior_sensitivity` — `$profile_id`: a bare upstream identifier
  with no measurements attached, removed because it still identifies a
  pedon

The reasoning recorded in that script draws the line this way: *a
per-fold RMSE is a statement about a method; a 1,095-element vector of
measured SOC is the dataset.*

**One inconsistency in the audit trail, reported rather than tidied
away.** The committed manifest lists 11 bundles, while the script that
wrote it declares 13 — it also strips `case_cerrado_results`
(`$profiles`, 1,095 × 70, and `$emb_cols`) and `causal_cerrado_real_v2`
(`$profiles`, 3,077 × 11, described in the script as the widest real
WoSIS pull in the package). The committed CSV predates those two
sections and was not regenerated; the script is not re-runnable once it
has run, because its inputs no longer exist.

The discrepancy is in the paperwork, not in the artefacts. Both bundles
were checked directly and both have had their payload removed:
`$profiles` and `$emb_cols` are absent from each, and both carry the
strip note. The manifest under-reports what was removed; it does not
over-report it.

## 4. Geographic extent

Every coordinate pair reachable inside every shipped artefact was
extracted and tested against a deliberately generous Brazil bounding box
and against the United States:

|  |  |
|----|----|
| Coordinates shipped | **7,392** |
| Falling inside Brazil | **7,392** |
| Falling inside the United States | **0** |
| Extent | longitude −60.50 to −44.00, latitude −22.00 to −2.90 |

The Brazil box is loose on purpose: the claim under test is *“these
points are not in the United States”*, and a loose box makes that harder
to pass, not easier.

Of these, 6,075 belong to the three synthetic grids. The remaining 1,317
were checked individually:

- **424 in `capstone_campaign_results.rds`** — 416 fall exactly on a
  regular 10 × 10 lattice spanning −50° to −48° longitude and −16° to
  −14° latitude at a spacing of exactly 0.222222°. The other 8 sit on a
  0.2° lattice and are the observation sites of a data-assimilation
  demonstration. Real soil profiles do not fall on an exact lattice;
  these are simulation grids.
- **893 in the two `fixture_*` bundles** — synthetic by construction and
  documented as such.

### 4.1 The stronger test: collision against the real coordinates

A bounding box tests where points *are*. The check that the accusation
actually calls for tests what they are *not* — whether anything still
shipped coincides with the real coordinates that once were here.

The pre-strip state of all 27 bundles is recoverable from commit
`d8c1998`, the parent of the strip. Reading them back and subtracting
what survives gives the coordinate universe the strip removed: **3,047
distinct real coordinates**, from `case_cerrado_results` (1,081),
`causal_cerrado_real_v2` (2,872), `causal_cerrado_real` (1,081),
`piml_external_anchors` (1,060), `piml_wosis_cerrado` (1,060),
`capstone_campaign_results` (250), `soildata_uberaba_bd` (83) and
`temporal_cerrado_results` (10). That set is computed by difference
rather than read from the manifest, which is why it is trustworthy where
the manifest is not — see §3.

Intersecting everything still shipped against those 3,047 coordinates:

| Artefact                    | Points | Collisions |
|-----------------------------|--------|------------|
| `br_amazon`                 | 2,025  | **0**      |
| `br_cerrado`                | 2,025  | **0**      |
| `br_pantanal`               | 2,025  | **0**      |
| `fixture_wosis_like`        | 833    | **0**      |
| `fixture_soildata_like`     | 60     | **0**      |
| `capstone_campaign_results` | 424    | 1          |

The three exported datasets are further confirmed as complete regular
lattices: 45 × 45 with all 2,025 cells filled and a single constant
spacing on each axis (0.009091° for `br_amazon` and `br_pantanal`,
0.007955° × 0.006818° for `br_cerrado`). Real soil profiles do not fill
a rectangular lattice.

**The single collision, run down.** It is the point (−47.9, −14.1), row
8 of `capstone_campaign_results$temporal_results$obs_locations`, which
also appears among the coordinates removed from
`temporal_cerrado_results`. It is not a leaked profile. What was removed
from that bundle is itself a perfect 10 × 10 grid at exactly 0.2°
spacing spanning −47.9 to −46.1 by −15.9 to −14.1: raster cell centres
of a simulation domain, holding gridded NDVI, precipitation and
temperature, not soil sampling sites. Both bundles describe the same
domain, so they share its grid nodes. The eight rows the package still
ships carry two columns, `lon` and `lat`, and no measurement of any
kind.

### 4.2 The automated guard

`tests/testthat/test-no-third-party-data.R` enforces this on every test
run. It walks each shipped bundle recursively to depth 12 and descends
where a names-based check cannot see: into `lm`/`glm`/`nls` internals —
`$residuals`, `$fitted.values`, `$qr`, `$effects` — and into the
enclosing environments of closures. It was written after a bundle that
had been “slimmed” by nulling `$model` turned out to still ship
residuals named by real WoSIS profile ids, in three places the author
believed were empty. It flags coordinate columns, columns and row names
holding upstream-shaped identifiers, and atomic vectors keyed by them. A
companion test constructs that exact defect and asserts the scanner
fires on it, on the principle that a guard never shown to fail is not a
guard.

## 5. Provenance records

Each bundle records the script that produced it and that script’s hash.
Of the 27 artefacts, 16 carry a verifiable `script_sha256`, and **all 16
verify** — recomputing the hash from the script on disk reproduces the
recorded value.

One caveat for anyone checking by hand: `edaphos` hashes a script’s
*lines joined by newline* through `digest`, not the raw file bytes, so
`shasum -a 256 <file>` will legitimately disagree with a recorded
`script_sha256`. The convention is implemented in `.script_hash()` in
`R/provenance.R` and travels with its own algorithm tag. Comparing the
two conventions looks like a tampered file and is not one.

## 7. How to verify this yourself

Every claim above is reproducible from a checkout. None of these
commands needs network access.

Regenerate the full inventory, including the §4.1 collision check — it
reads the pre-strip bundles back out of git, so it needs no network and
no archived copy (~4 seconds):

``` bash
Rscript tools/provenance-inventory.R
```

Run the automated guard of §4.2, and the companion test that proves it
fires:

``` bash
Rscript -e 'pkgload::load_all("."); testthat::test_file("tests/testthat/test-no-third-party-data.R")'
```

Search every blob that has ever existed in the repository:

``` bash
sh tools/history-term-scan.sh "datsoilspc|svrc_example|KSSL|Kellogg|NCSS|RaCA|SSURGO|STATSGO"
```

That command prints `1 kssl`, `58 ncss` and `1 raca`, and prints nothing
for `datsoilspc`, `svrc_example`, `Kellogg`, `SSURGO` and `STATSGO` — a
term that never existed produces no line at all. It counts **raw
bytes**, so its three non-zero lines are the coincidences dissected in
§2.3 plus the `aqp` documentation hyperlink of §2.2. The next command is
the one that searches content rather than bytes.

Search the decompressed content of every shipped data artefact — this is
the search that matters, since raw-byte searches produce the false
positives described in §2.3:

``` bash
for f in inst/extdata/*.rds data/*.rda; do gunzip -c "$f" 2>/dev/null | grep -oa -i -E "KSSL|NCSS|RaCA|SSURGO|STATSGO|Kellogg|USDA|NRCS|datsoilspc|svrc_example" | sort -u | sed "s|^|$f: |"; done
```

Read the manifest of everything removed in the strip:

``` bash
cat data-raw/build/stripped_elements.csv
```

## 8. What this inventory does not establish

Three limits, stated so that the document is not read for more than it
supports.

1.  **It covers this repository.** It says nothing about any other copy,
    fork or distribution of the package.

2.  **A name search cannot find data hidden under a different name.**
    The coordinate audit in §4 is the stronger evidence, because it
    tests the *content* rather than the labels: no point in any shipped
    artefact lies in the United States, and the non-synthetic
    coordinates all fall on exact lattices. Anyone wanting a still
    stronger check should search for a known pedon identifier or a known
    coordinate pair from the dataset they believe was copied; §7 shows
    how.

3.  **It reports what WoSIS declares.** The licence table in §2.1 is
    WoSIS’s own metadata, carried through unmodified. This document
    verifies that the package handled those records consistently with
    that metadata; it does not independently audit ISRIC’s licensing of
    its upstream contributions.
